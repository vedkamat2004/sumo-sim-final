Direct vs alternate is decided in controller/DynamicReroutePolicy.py with a 3-stage gate:

Start state
Hero starts on direct plan (hero_current_plan = "direct").
It can switch at most once (hero_has_rerouted flag).
Congestion trigger
_check_route_congestion() scans upcoming edges on the direct route from current position.
For each edge, it computes density:
density = vehicle_count / (edge_length / 100) (vehicles per 100m)
If any edge density > congestion_threshold (set to 0.5 in main.py), congestion is considered detected.
ETA comparison gate (actual decision)
On congestion, it computes:
direct_eta = _estimate_path_time(current_edge, direct_path)
alt_eta = _estimate_path_time(current_edge, alternative_path)
_estimate_path_time() does per-edge travel time:
reads edge mean speed (traci.edge.getLastStepMeanSpeed)
reads occupancy (traci.edge.getLastStepOccupancy)
applies congestion penalty to speed:
congestion_penalty = 1 + max(0, occ - 0.10) * 5
effective_speed = max(0.3, speed / congestion_penalty)
sums edge_length / effective_speed across remaining edges
It reroutes only if alternative is significantly better:
required_gain = max(20.0, 0.25 * direct_eta)
condition: alt_eta + required_gain < direct_eta
If true:
switch to alternative,
lock reroute (hero_has_rerouted = True),
save ETA snapshot for reporting.
If false:
stay on direct ([REROUTE SKIPPED]).
Execution detail in simulation:

In core/STR_SUMO.py, the hero is re-evaluated every step even if it hasn’t changed edge yet, so this logic can trigger while waiting at the same node.
So in short:

Congestion alone does not force reroute anymore.
Reroute happens only when ETA says alternate wins by a clear margin.

Summarizing switching logic
Great question. Here is exactly how it judges:

It uses a two-stage judgment:

Congestion check first
It looks ahead on the direct path and checks traffic density on upcoming roads.
If congestion is not high enough, it keeps direct.
Time comparison second
If congestion is high, it estimates travel time for both options from the hero’s current position:
direct path ETA
alternate path ETA
It only switches if alternate is clearly better, not just slightly better.
It requires a minimum benefit margin before switching (a fixed minimum plus a percentage margin).
So “judge” means:
Is direct congested? and then Is alternate significantly faster right now?

About “every stop” decision:

It evaluates the hero repeatedly at each simulation step (including while waiting/stuck on the same edge), so yes, it keeps checking continuously.
But route switching is one-time in this setup:
starts on direct
may switch once to alternate
after switching, it does not switch back and forth.
So:

Checks happen continuously
Plan change happens at most once (direct -> alternate)
